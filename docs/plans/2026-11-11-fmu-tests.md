# FMU-Based Tests Implementation Plan

**Goal:** Experiments written once run against a given FMU or a Modelica model exported as an FMU, through FMPy, with the same run settings, parameters, errors and comparisons as native runs.

**Architecture:** A new internal package `mtools.internal.fmu` sits beside the OMC backend. In the parent process it reads the model description, checks the run against it and returns one resolved run. A child Python process (`python -m mtools.internal.fmu.child <run dir>`) then runs FMPy, started through the backend's existing process runner, and exchanges files with the parent in the run directory. Exported FMUs are OMC builds with a different last script stage, so they share the existing cache, variants and work directory. `simulate_run` dispatches by build type, and `mtools.testing` gains `rtol` and `interpolate`.

**Tech Stack:** Python 3.11, FMPy 0.3.32, OpenModelica 1.27.2, hydra-zen, pandas, numpy, pytest.

**Spec:** `docs/specs/2026-11-11-fmu-tests-spec.md`. Tickets: #88 (parent), #89–#107. Task N implements ticket #(88+N).

## Global Constraints

- `fmpy~=0.3.32` is the optional extra `modelica-tools[fmu]`, and the `dev` extra pulls in the same pin. FMPy is imported only for FMU runs, in the child process and in the parent's model-description checks.
- The missing-FMPy error is exactly `ImportError("FMU runs need FMPy: install modelica-tools[fmu]")`, raised before anything is built or exported.
- Exports are FMI 2.0 only: `buildModelFMU(<model>, version="2.0", fmuType=<fmu_type>, fileNamePrefix="model")`.
- `fmu_type` is `"me"` or `"cs"`. Exported FMUs default to `"me"`. A given FMU with `fmu_type=None` runs ME if it offers it, otherwise CS.
- OMC's defaults: start 0, stop 1, interval (stop − start)/500, tolerance 1e-6. Every value is passed to FMPy explicitly. FMPy's own defaults, temp directories and `timeout` are never used.
- Every model-description problem (parameters, name map, `fmu_type`, solver, CS interval) is reported together in one `ConfigError`, under the header `Invalid run settings for '<model>':`, with each line naming its config path.
- Run headers match the native ones: `Simulation of '<model>' failed:`, `Simulation of '<model>' crashed with SIG…:`, `Simulation of '<model>' timed out after <N> s:`, and `Simulation of '<model>' reported warnings:` for a successful run that logged warnings.
- Result columns: `time` first, then `modelDescription.xml` order, named in the experiment's names. Types are `float64`, `int64` and `bool`. Parameter, calculated-parameter and constant columns are dropped, and so are String and Binary columns.
- FMU tests live in `tests/fmu/`, carry the `fmu` marker, point `MTOOLS_WORK_DIR` into pytest's temporary directory, and fail rather than skip without FMPy.
- Native cache keys, native runs and every existing public signature stay unchanged. `create_run` gains only the optional `fmu` argument.
- Commits use conventional-commit style. The checks are `uv run pytest tests`, `uv run mypy src tests` and `uv run isort --check-only src tests examples`, plus the examples suite for Task 18.

## Review Focus

1. **A Reference-FMU lists `time` as a variable** (FMI 2.0 `causality="independent"`; FMI 3.0 `Float64 name="time"`). The result must not get a second `time` column. Test in Task 1 (`test_result_columns_follow_the_model_description`).
2. **FMI 3.0 FMUs ship `binaries/x86_64-linux`, not `linux64`.** The file check must accept either platform directory for its FMI version, or every FMI 3.0 given FMU is rejected. Test in Task 3 (`test_fmi3_fmus_run`).
3. **The exported FMU's translation runs twice** (`translateModel`, then inside `buildModelFMU`). Translation warnings must still be logged once. Test in Task 4 (`test_export_logs_translation_warnings_once`).
4. **A Hydra override gives a float where an Integer parameter is wanted** (`settings.parameters.n=2.0`). An integral float is accepted as that integer, `2.7` is rejected, and `True` is rejected for Real and Integer. Test in Task 8 (`test_integer_parameter_accepts_integral_float_and_rejects_bool`).
5. **The parent is interrupted while the child runs** (Ctrl-C in a long sweep). The child's process group is killed and the run directory deleted, as for native runs. Test in Task 11 (`test_interrupt_kills_the_child_and_removes_the_run_directory`).
